# UI 缺陷与验证

范围：2026-11-12 用户反馈的正式界面问题。最后更新：2026-11-12。

## BF-UI-01：供应商名称挤压与列错位

- 问题证据 E-1：用户截图中 RoseAI 名称、协议与余额列错位，页面大片留空。
- 原因证据 E-2：旧样式把拖动把手设为 absolute，脱离网格；新七列定义仍把它当作第一列，导致自动排布的头像与名称落入过窄列。多层样式同时保留了旧网格规则。
- 方案：列表与详情分开；列表只有选择与排序，完整配置与状态进入右侧详情。
- 变更：`GatewayProviders.tsx`、`rosecode/ProviderWorkspace.tsx`、`provider-selection.ts`、`provider-workspace.css`；列表使用独立类名，详情通过 portal 进入右侧面板。
- 验证 E-6 / E-11：多种尺寸和真实 RoseAI 三条配置已查看。筛选后选择、折叠关闭条目、目标消失和空列表的选择回归测试通过。
- 审查状态：[V] 已实际验证主要路径；[T] 等待用户验收。
- Git 状态：无 Git 元数据；未创建提交或快照。
- 回退：可按本轮针对性源码变更手工恢复；无可引用的 commit。

## BF-UI-02：搜索面板样式与焦点不一致

- 问题证据 E-3：用户截图中的搜索输入框出现不合适的方形焦点边框，结果列表仍为旧页面结构。
- 原因证据 E-4：`CommandPalette.tsx` 沿用旧面板结构，portal 不继承 shell 局部样式；全局 focus-visible 规则作用于输入框。
- 方案：专属搜索工作区，分组导航、语义完整的 combobox/listbox、统一输入容器焦点、关闭恢复焦点、键盘边界与 Tab 约束。
- 变更：`CommandPalette.tsx`、`rosecode/palette.css`、`use-dialog-focus.ts`；输入焦点由完整搜索容器承担。
- 验证 E-7：深浅色和短窗口已查看；空结果键盘边界、跳转、关闭焦点恢复、抽屉 Tab 约束已验证。
- 审查状态：[V] 已实际验证主要路径；[T] 非拉丁输入法组合输入尚未逐种实测。
- Git 状态与回退：同 BF-UI-01。

## BF-UI-03：仅换组件，页面结构仍旧

- 证据 E-5：上一版 `shell.css` 只调整旧布局作用域，首页仍组合原来的通用行卡片。
- 修正：原“新版 UI 已完成”的表述过度；本轮以独立顶栏、供应商工作区、首页组合与搜索结构作为验收对象。
- 变更：独立 `WorkspaceBar`，首页统计与 Agent 卡片、连接步骤、供应商工作区、接入卡片、路由看板、统计组合；Claude 合并页签，保持未保存草稿。
- 验证 E-6 至 E-11：对应主要页面已查看；1954 项前端测试通过，2 项跳过。
- 审查状态：[V] 结构已改变；[T] 视觉满意度待用户验收。
- Git 状态与回退：同 BF-UI-01。

## BF-UI-04：内容宽度额外扩展 20px

- 原因：旧 `.gw-content` 使用 `width: calc(100% + 20px)` 和负边距，新的页面留白与之不匹配。
- 变更：`rosecode/shell.css` 恢复工作区的明确宽度，去掉负边距；供应商页只由集合与详情分别滚动。
- 验证 E-6：DOM 实测宽度和截图检查，最小窗口未横向裁切。
- 状态：[V] 验证通过。Git 状态与回退同 BF-UI-01。

## BF-UI-05：收起侧栏出现横向滚动与焦点框裁切

- 原因：隐藏分组标题仍影响最小内容宽度，外描边被滚动容器裁切。
- 变更：`rosecode/shell.css` 约束标题宽度与横向溢出，改用按钮内描边；保留分组高度以减少收起时的垂直跳动。
- 验证 E-8：DOM 实测横向溢出为 false，提示文字在侧栏右侧显示。
- 状态：[V] 验证通过。Git 状态与回退同 BF-UI-01。

## BF-UI-06：深色内容与浅色原生标题栏不一致

- 变更：`native-appearance.ts` 调用当前安装的 Tauri Window.setTheme；新增只允许 main 窗口设置主题的 capability，主窗口与独立 ClaudeMom 共用同步函数。
- 验证 E-11：原生 Windows 窗口切深色后标题栏同步，切回浅色正常。
- 状态：[V] Windows 已验证；其它平台仍沿用原生外壳。Git 状态与回退同 BF-UI-01。

## BF-UI-07：首次加载显示零统计，缺 Key 条目显示占位 Key 数

- 原因：payload 为 null 时直接用空数组统计；占位 Key 的历史 keyCount 被当作可用 Key 展示。
- 变更：`ProviderWorkspace` 区分 ready/loading/error；RoseAI 缺 Key 时显示待配置，并禁用直接同步与测试。
- 验证 E-12：加载与失败状态渲染测试通过，真实空池仍可显示零；最终原生界面已复核加载统计为破折号、缺 Key 条目显示待配置、上游同步入口禁用。
- 状态：[V] 前端测试与原生复核通过。Git 状态与回退同 BF-UI-01。
